## Findings

### Required: Node-only type mismatch at tests/market-fetch.spec.ts:15

The explicit Node-only TypeScript check fails with TS2552:

```text
Cannot find name 'RequestInfo'. Did you mean 'RequestInit'?
```

Reproduce on the original PR head:

```sh
node node_modules/typescript/bin/tsc --noEmit --target ES2022 --module NodeNext --moduleResolution NodeNext --strict --skipLibCheck --allowImportingTsExtensions --lib ES2022 --types node tests/market-fetch.spec.ts
```

Use `input: Parameters<typeof globalThis.fetch>[0]`, which derives the
string/URL/Request input from the actual host signature. This single-line
local probe passed the same type check and retained 16/16 tests. It was
reverted after verification; no contributor fork or production source was
changed. Adding the DOM library is unnecessary.

This is **not** a claim that current `npm test` or CI fails. `tsconfig.json`
includes only `src`, and the compatibility script typecheck does not include
the new file, so those gates miss this test-file type error.

### Non-blocking: assertions do not cover all failure semantics

- The Binance HTTP test at lines 64-71 asserts a message prefix, not the
  advertised 200-character truncation. Removing truncation temporarily still
  passed all 41 market tests.
- The native report leaves lines 223-224 and 226-228 uncovered: shared
  `safeFetch` network rejection and non-2xx handling for the other providers.
  Replacing its network-error context temporarily also passed all 41 tests.
- Suggested follow-up: assert the complete truncated suffix and add one
  representative OKX network failure / HTTP error case. No production
  refactor or all-provider Cartesian test expansion is required.

These gaps limit the regression claims; they do not invalidate the line
coverage result or the useful endpoint, parsing and limit assertions.
