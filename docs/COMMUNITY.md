# Community Intake and Future Chat Group

Decision recorded: 2026-11-14 (Asia/Shanghai).

Keep collecting useful contributions now. Consider a voluntary chat group once
there are sustained participants and a concrete need for synchronous exchange.
No group is being created or advertised as live in this update.

Reuse an existing thread when relevant. Do not repeatedly post the same call or
send unsolicited invitations to contributors. Mature libraries, teaching
baselines, prototypes and honest negative results are all useful.

## Intake Loop

`submission -> needs-info / reviewed -> small PR -> CI -> merged -> credited`

Request a primary link, concrete use, license/data rights, exact version and
what was actually run (or NOT_RUN). Ask for a minimal reproduction for bugs.
Preserve authorship. Thank people during review and after merge, with specific
credit and an invitation to keep collaborating. Review is not automatic acceptance.

Use the existing weekly FICC review process; see [FICC rules](../ficc/CONTRIBUTING.md).
It depends on client/connectivity availability and does not merge unattended.
This update does not add an automation, a response-time guarantee or an npm release.

## Readiness for a Group

Reassess when these signals exist, rather than inferring an active community
from stars alone:

- Several independent participants repeatedly use, report, review or contribute.
- Recurring installation/research discussions would benefit from live exchange.
- Maintainers have capacity for moderation and publishing useful outcomes.
- A clear purpose and conduct/privacy rules can be stated before inviting anyone.

The 2026-11-14 public repository snapshot was 69 stars and 7 forks. This is
visibility, not an active-user count or a declaration that a group is ready.
Participant retention, response time and group value remain UNMEASURED.
These are assessment signals, not a new numeric launch promise.

## Boundaries if a Group Opens Later

- A maintainer explicitly decides the platform and launch date; joining is opt-in.
- Nobody must join a group to get support or submit a contribution.
- Keep bugs, decisions, examples and accepted fixes traceable on GitHub.
- Ask permission before quoting or publishing someone else's chat content.
- Never collect credentials, private strategies, customer data or paid datasets.
- Research/software discussion only: no return promises, trade signals or paid
  investment-advisory claims. A resource listing is not validation of performance.
- Credit contributors publicly without publishing private contact information.
