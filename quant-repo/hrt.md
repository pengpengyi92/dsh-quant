# Hudson River Trading 开源 repo 专刊

HRT 的 GitHub 足迹极少——没有成体系开源生态。它的公开资产不是代码，
而是**算法文化与谜题**。

## 现状

- 官方 repo：零星小型工具，无框架级开源
- 技术演讲/论文：少量；员工对外发声少（保密协议）
- 真正的「公开资产」：流传在互联网上的 HRT 面试谜题——算法题的
  难度成了他们的品牌（与 Jane Street 面试谜题并称行业最难）

## 为什么不开源

1. **自营自由 + 保密文化**：没有客户品牌需求，也没有开源获客动机
2. **算法即策略**：HRT 的代码边界就是策略边界（不像 JS 的库/策略分层）
3. **招聘不靠开源**：谜题与薪资足够吸引人

## 对 dsh-quant 的启发

1. **「算法即策略」的警示**：当基础设施与策略不分层，开源就无从谈起——
   dsh-quant 的六域设计刻意把「方法层」与「参数/策略层」分开，
   正是为了保住「可开源的部分」
2. **谜题是免费广告**：HRT 用面试题完成技术品牌——我们的手算测试
   与 demo 也可以成为这种「可传播的公开资产」
3. **光谱再补一点**：HRT 介于 Citadel（全封闭）与 JS（框架级开源）
   之间——**有文化输出（谜题），无代码输出**
